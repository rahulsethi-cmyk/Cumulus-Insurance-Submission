Speaker Notes

Hero

Welcome everyone. I'm Rohan, and today I want to show you how we used Agentforce to solve a very real, very expensive problem inside a P&C insurance carrier called Cumulus Insurance. Cumulus works with independent agents who send in quote requests — called submissions — for mid-market commercial prospects. The story I'm about to tell starts with an email inbox and ends with a fully autonomous agent that processes those submissions end to end.

Challenge

Here's the core problem. When an independent agent sends a submission email to Cumulus, Email-to-Case creates a Salesforce Case and assigns it to an operations user. That ops user then has to open the email, read through a mix of plain text, tables, and attached documents, extract all the relevant fields — insured name, coverage type, total insured value, SIC code, effective date — and manually key them into Salesforce. Then they can start the actual work: risk clearance and appetite check. This swivel-chair process, toggling between the email client and Salesforce, can take 30 to 45 minutes per submission. And every hour that passes is an hour a competing carrier might respond first.

Solution

Our solution is an Agentforce agent that gets assigned to the Case the moment Email-to-Case creates it. The agent uses RAG — retrieval-augmented generation — to query Salesforce's Data Cloud Vector DB, which has already chunked the raw email content and any attachments. The agent extracts structured fields, populates the Case in Salesforce, then immediately runs the risk clearance and appetite check rules. If the submission clears, it routes the Case to an underwriter automatically. The entire process that used to take days now completes in minutes — with no human touchpoints unless the agent flags something for review.

Design

A few deliberate design choices worth calling out. I kept the agent's topic scope very narrow — it only handles submission intake, risk clearance, appetite evaluation, and routing. It has no access to unrelated CRM records and can only write to designated submission fields. This matters in financial services because a too-broad agent is a compliance and audit risk. I also built a hard escalation path: if the agent's confidence in extracted data is below threshold, or if a risk rule produces an ambiguous result, it stops and flags the case for human review rather than guessing. Every action is logged against the Case record for a full audit trail.

Testing

I validated the agent using Einstein Conversation Testing in Salesforce, plus a manual spot-check against 10 representative submission emails I used as ground truth. Field extraction accuracy came in at 95% across those cases. I also stress-tested specific edge cases: emails with no structured data at all, submissions with missing TIV, risks outside the appetite matrix, duplicate submissions, and attachment-only emails with no body. The agent handled all of them either fully or with a graceful escalation — except duplicate detection, which is partially implemented and flagged as a Phase 2 improvement.

Impact

Let me ground these numbers. The 70% reduction in submission-to-quote time is based on a baseline of 3–5 days for manual processing; with the agent handling intake, risk, and routing automatically, that becomes hours. The 95% field accuracy is a measured result from our 10-case test set. The 60% reduction in ops touchpoints is projected — it assumes the agent handles clean submissions autonomously and only escalates edge cases. And the ops cost reduction is real: you can deploy the same ops headcount to handle exceptions and complex cases rather than routine data entry.

Roadmap

What I've built for this capstone is Phase 1 — the intake, clearance, and routing loop. Phase 2 extends the agent into quote generation: it pre-populates rating inputs from the Case data and integrates with the rating engine, so underwriters spend their time reviewing and approving rather than data-entering. Phase 3 is the proactive layer — the agent reaches out to independent agents to request missing information, automates renewal submissions, and surfaces predictive appetite scoring. Each phase builds on the Data Cloud foundation we established in Phase 1.

Close

Here's the one thing I want you to take away: the bottleneck in P&C submissions was never the underwriter — it was the 30 to 45 minutes of manual triage that had to happen before the underwriter ever saw the case. Agentforce eliminates that bottleneck entirely. Cumulus Insurance now has an agent that reads every submission email, extracts every field, runs every rule, and routes every case — autonomously, accurately, and at any scale. That's not a productivity improvement. That's a structural change in how the business operates. Thank you.

Topics, Actions &
Grounding Strategy

Narrow, well-defined scope: ingest submission data, validate it against business rules, and route it — no broader CRM access, no free-form actions.

Submission Intake Risk Clearance Appetite Evaluation Underwriter Routing Data Validation Case Status Update Missing Data Escalation

📝

Audit Trail

Every field population and rule execution logged against the Case record for compliance and review.

🚨

Human Escalation Path

Low-confidence extraction or ambiguous risk rules trigger a human-review flag rather than autonomous continuation.

PII Handling
